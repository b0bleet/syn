How close can open weights get to Jev?

2026-09-28

Jev, TypeSafe's System One model, does one narrow thing well. You send some text and a closed set of options, and you get back a probability for each option. It doesn't generate text, so it's fast, and the probabilities are meant to be calibrated. We wanted the same thing built only from open weights, so we built syn. It speaks the same System One API, so typesafe-sdk code works after changing base_url.

This post covers what we measured: a zero-shot baseline, a tiny trained head that closes most of the gap, and the several things that didn't work.

Zero-shot: often right, confidence meaningless

The simplest readout needs no training. Put the options in the prompt as lettered choices, run one forward pass, read the next-token log-probabilities of the letters, and softmax over them. Nothing is generated.

On AG News (4 topics, all four offered on every row) with Qwen3-0.6B, this scored 0.698 top-1 on 1,000 test rows. Worse, its expected calibration error was 0.267: it was often very confident and wrong.

A 0.8M-parameter head on frozen features

The second readout keeps the backbone frozen. We run Qwen3 once over each training row and cache its final hidden states: every token of the text, plus one pooled vector per option, each option encoded on its own. A small cross-attention head then learns to score options: each option vector queries the text's token vectors, and the match becomes that option's logit. It has about 0.79M parameters. On cached features an epoch takes under two seconds, so the expensive part is the single feature pass (about 5 minutes for 4,000 rows on a laptop GPU).

4,000 train / 500 validation / 1,000 test rows. Latency measured on Apple silicon (MPS). Jev's 0.875 was measured on its own sample of AG News, not on our 1,000 rows, so it isn't a head-to-head result.

Paired on the same rows, the head beats zero-shot by +0.171 (95% CI 0.140–0.205). It fixed 249 rows and broke 78.

The control row matters most. We score each option set against a different row's text. If the head were learning which options tend to be right regardless of the text, the control would stay high. It lands at 0.250, exactly chance for four options, so the head is reading the text.

On banking77 (77 customer-service intents, 3–8 options sampled per row) the head went from 0.824 to 0.911, ECE 0.019, control 0.213. Zero-shot is already decent there because the intent names echo the customers' own wording.

What didn't work

  • Zero-shot binary spam on the 0.6B model. On eight test messages it scored 4/8, the same as always answering one label. The prompt's wording, not the message, decided the answer: two phrasings caught no spam at all, a third caught 3 of 4 but flagged every normal message as spam too. Don't ship zero-shot yes/no on a model this small.
  • Likelihood scoring on long options. Scoring each option's text as a continuation of the context, corrected for its prior, works for short label words. On long, descriptive options it collapsed to 0.547 on our synthetic routing set, where the letter readout got 0.922.
  • Making options independent with an attention mask alone. Hiding the options from each other sounds like it should remove position effects. Zero-shot it made accuracy worse and still wasn't order-invariant. Invariance came only with a trained readout.
  • Letter position bias. The letter readout strongly prefers whatever sits in position A. Averaging over rotations of the option order fixes which option wins, at the cost of one pass per rotation.
  • Training longer. The head's best validation score came at epochs 1–3; after that it overfit. Keep the best-validation checkpoint, not the last one.

Images, almost for free

Qwen3.5-4B has a vision encoder, so the same letter readout scores labels for an image. On 200 Imagenette photos (20 per class, all ten class names offered) it got all 200 right, with a median top-label probability of 0.993. Plain gray images drew the same label every time, so the answers come from the pictures. Imagenette's classes are easy to tell apart, though. This shows the pipeline works end to end, not how a hard task will go.

What runs on sifty.dev today

The hosted API at sifty.dev runs the zero-shot letter readout on Qwen3.5-4B, on one always-on GPU, in about a second per call. The trained head isn't live. A head trained on AG News has learned AG News; whether one head holds up on labels it never saw is the open question, and syn transfer exists to measure it. Until then, treat the hosted probabilities as a ranking, not a calibrated score, and check your labels on a few real examples.

Reproduce it

Everything above runs from the repository. The AG News numbers:

uv sync --extra local --extra hub --locked
uv run --extra hub python scripts/download_data.py
for split in train validation test; do
  uv run --extra local syn features data/agnews/$split.jsonl --out runs/feats/agnews-$split.npz
done
uv run --extra local syn train-head runs/feats/agnews-train.npz \
  --validation runs/feats/agnews-validation.npz --out runs/head.safetensors
uv run --extra local syn eval-head runs/head.safetensors runs/feats/agnews-test.npz

eval-head prints accuracy, ECE and the shuffled-context control together. syn bench sends identical System One requests to any set of servers that speak the API, Jev included if you have a key, and reports accuracy, calibration and a paired bootstrap between them.
